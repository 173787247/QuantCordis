# QuantCordis 路线 —— 按组件决定复用还是自建

> 背景: 用户先问过「要不要重写老师的系统」
> 最初答「不重写」 而那个论证建在坏数据上（茅台首行 −4.6572 招行 5 处断裂）
> 后来连续发现架构缺陷（收盘后引擎跳过 → 日K 策略是死的）
> → 用户给出了按组件拆的判断 —— 这份文档就是把它落下来

---

## 一、用户定的分工（原文意思）

```
① miniQMT / QMT → 直接用
② data（数据采集）→ 直接用 「也有可以采集的」
③ 13 个策略的程序 → 复用 「省去重新开发」
④ 剩下的 → 自己来
```

## 二、技术上的落地方式（已核实可行）

```
① QMT → 沿用 xtdata 接口 （新内核不换数据源）
 实测已验证: none / front / back 分别是什么 （见 PRICE-CONVENTIONS.md）
 → 新内核存的仍然是xtdata 的 none 只是表结构自己定

② data → 沿用现有采集能力
 → 但落库结构重做:
 · 存不复权价 + 复权因子（既有表没有因子列 → 这是必须重建的原因）
 · 停牌日标 suspended 不存 0
 · 每条带来源与抓取时间 → 可追溯

③ 13 个策略 → import 复用 不搬代码
 已核实: lib/strategy_registry.py 的 strat_* 是纯函数
 签名: (code, market, capital) -> {side, strategy, reason}
 → 自带回测器 → 新回测层直接调用
 复用清单（13 个 全部可用）:
 macd_5min · macd_1d · dual_ma_5min · ma20_hold · multi_factor
 dragon · rsi_reversal · boll_revert · bias_revert
 turtle_donchian · grid_classic · ml_prob · chan_third_buy

④ 其余 → 自建 :
 · 数据表结构（带复权因子）
 · 回测层（喂数据给复用的策略 自己算净值与超额）
 · 完整性审计（能失败 不过关就拒绝出数）
 · 引擎 → 暂缓 —— 先让回测结论可信 → 再谈执行

```

## 三、为什么这样分（判据）

```
 判据: 缺陷来自"数据结构"→ 重建 · 来自"代码逻辑"→ 修或换
 · 数据表没有复权因子 → 结构问题 → 重建
 · 行情接口（xtdata）→ 能用 → 不换
 · 策略函数 → 是纯函数 → 复用
 · 引擎时段判据漏了收盘后 → 逻辑问题 → 修
 → 结果: 要重建的只有"数据层 + 回测层" 而不是整个系统
 → 这正是 QuantCordis 的范围
```

## 五、 与参考实现的关系（不变）

```
 · 只修 bug 不加功能
 两套共用数据库 → 新内核只读既有表 + 写自己的新表
 而"新的长好了，旧的自然不用了" —— 不是推倒重来
```
