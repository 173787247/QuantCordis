# 价格口径 —— 实测结论与数据层设计依据

> 全部结论来自实测，不是文档推断
> 测的对象: 600519.SH（贵州茅台）· 窗口 2026-06-01 → 2026-07-15（含除权日）

---

## 一、xtdata 的 `dividend_type` 有五种，实测各自是什么

| 取值 | 实测（茅台末日 2026-06-30）| 是什么 |
|---|---|---|
| `none` | 1288.0000 | 真不复权价 （真实成交价）|
| `front` | 1288.0000 | 前复权（以最新为基准，历史价减掉分红）|
| `back` | 8077.9412 | 后复权（历史价乘因子）|
| `front_ratio` | 1288.0000 | 与 `front` 同值 → 不是"因子" |
| `back_ratio` | 9878.3856 | 与 `back` 同值 → 也不是"因子" |

 重要纠正: `front_ratio` / `back_ratio` 这两个名字看起来像复权因子
实测: `back_ratio ÷ none` = 9878.3856 / 1288.0 = 7.6696
 `back_ratio 首 ÷ front_ratio 首` = 1100.2095 / 143.4516 = 7.6696
→ 两处比值相同 → 它们是复权价 不是因子
→ xtdata 在这个版本里不直接给复权因子 → 因子必须自己从价格推

## 二、 前复权的本质被抓住了：减掉分红

```
窗口 2026-06-01 → 07-15 的逐日对比（摘录）:
 日期 none front 差
 2026-06-25 1212.1000 1184.0758 28.02
 2026-06-26 1168.6300 1168.6300 0 ← 除权日
 2026-06-29 1194.9600 1194.9600 0
 06-25 之前，差额恒定 28.02
 1309.60 − 1281.58 = 28.02 · 1212.10 − 1184.08 = 28.02
→ → 28.02 = 每股分红
 → 前复权 = 从历史价里减掉历次分红
 → 而 06-26 起两者归一 → 06-26 是除权日
```

### → 这解释了两个一直没想通的现象

```
① 为什么会有负价格
 前复权是减 → 长期高分红 + 低股价 → 减到负数
 实证: 000627.SZ 于 2023-05 开=低=收=−0.11
 集中: 4 只股票占全部非正行的 52% （000627 · 000622 · 000040 · 000005）

② 为什么回测不可复现
 前复权以最新价为基准 → 每次分红都重算全部历史
 → 同一段回测在不同时间跑 → 输入价格不同→ 结果不同
 → 实证: 昨天那 10 组回测里，茅台的"买入持有"算出 38,087%
 而首行开是−4.6572 → 分母负数 → 倍数荒谬
```

## 三、数据层的设计（据此定下）

```
 存什么: 只存 `none`（真不复权价）
 → 它是事实 不随任何基准变化 → 可复现

 因子怎么来: 自己从价格推（因为 xtdata 不给）
 推法: 对每个除权日，用除权前后两日的 none 价与分红额算
 或者更省事: 直接用 back / none 的比值当累计因子
 → 实测末日的比值恒定 7.6696 hmm: → 需再验它是否逐日恒定
 备选: 从独立的分红送转表取 （若库里或 xtdata 有 → 下一轮查）

 回测怎么用: 我们自己算复权
 → 想用前复权 → 用"最新基准"算 想用后复权 → 用"起点基准"算
 → 两者都能从同一份 none 数据 + 因子算出 → 一套数据，两种视图
 → → 这才是"可复现"的含义: 数据是事实，视图是可重建的

 完整性检查（能失败）:
 · 任何价格 <= 0 → 拒绝 （因为 none 里不该有 有就是抓取坏了）
 · 相邻两日比值 >5 或 <1/5 且前一日有成交 → 标记断裂
 · 因子序列必须单调（后复权）或不增（前复权） hmm: → 待实测确认
```

## 四、 关键验证：换用 none 能根治哪个病

```
 拿库里最坏的几只去问 xtdata 的 none 口径 :

① 茅台 2016-07-01 → 07-06:
 none → 286.17 · 293.90 · 300.58 · 317.19 全部 >0 就是真实价
 front → −5.48723 · 2.2428 · …
 → → 库那个 −4.6572 就是 front 口径算出来的
 → 换 none → 这个病根治

② 但 000627.SZ / 000004.SZ / 000622.SZ / 000040.SZ 四只:
 none → 也全是 0.0000
 000622: 2025-01-02 → 2025-07-15 全 0（128 行 末行 2025-07-15）
 000040: 2025-01-02 → 2025-03-31 全 0（57 行）
 → → 它们的 0 不是复权造成的
 → 是那段时间根本没有交易（长期停牌 / 已退市）
 → 也就是说: 0 不是"病"，是"事实"
```

### → 两类病，两种治法（设计据此定下）

```
① 负数= 复权算坏
 → 换 none 根治 —— 实测茅台 286.17 完全正常
 → 这类是绝大多数（48,217 行里 29,406 行是负值/近零）

② 0= 停牌或退市
 → 不是病，不该"修" → 判据应当识别并标记
 → 数据层存 NULL 或标记 suspended —— 不存 0
 → 因为 0 在回测里会被当成一个真实价格 → 算出无穷大或零收益
 → 回测遇到停牌日: 跳过该日 或拒绝该区间（若停牌很长）

 → → 这就是"数据层重做"的具体内容:
 · 存 none（真价）→ 负数病根治
 · 停牌日标 suspended → 不落 0
 · 复权自己算 → 可复现
```


```
 我说过"换 none 能救 47% 的非正行" —— 错（这是我今天第四次修正自己）
 验法: 拿库里负数最多的那 4 只去问 xtdata 的 none 口径

 000627.SZ 6,038 行负数 → none 全 0
 000040.SZ 4,929 行负数 → none 全 0
 000622.SZ 658 行负数 → none 全 0
 000005.SZ 131 行负数 → none 全 0

 再看它们在 2026 年有没有数据:
 000627 · 000040 · 000622 · 000005 → 全部 0 行
 → → 它们全部已退市
 → 换 none 救不了已退市的标的 —— 数据源里就只剩占位 0
```

### → 正确的分界（据此改设计）

```
 我原来的分法: 负数可救 / 0不可救
 → 太粗 —— 因为"负数"里混着已退市的

 正确的分法: 还在交易 vs 已退市
 · 已退市 → 数据源里就是垃圾 → 任何复权口径都救不了
 → 唯一的办法: 排除
 → 而这也正好符合真实交易 —— 你不可能买一只已退市的股票
 · 还在交易 → front 可能被减成负 （茅台 2016-07-01 = −5.48723）
 但换 none 就正常（同一天 = 286.17）
 → 这才是"换 none"真正救的那一类

 → 股票池的判据（数据层与回测层都要用）:
 最近 N 个交易日有成交
 → 实测可用的判据: volume > 0 且 close > 0
 → 建议 N = 20（约一个月）—— 太短会放进刚停牌的 太长会漏掉刚复牌的
```

### → 库里"负数"到底是什么（重新解释）

```
 11,756 行负数 · 只涉及 4 只 · 4 只全部已退市
 → → 它们本来就该被排除 → 不算"数据病"，算"股票池没筛"
 而 2024 年后负数归零 —— 因为那 4 只在 2024 年前就退市了
 → 所以"2024 年后干净"这个观察是对的，但原因不是数据变好
 → 是那几只退市了
```

## 七、 决定性：股票池判据救不了断裂病

```
 我上一轮的假设: 有了"最近 20 个交易日有成交"这条池子判据
 → 断裂病可能顺带被解决（因为退市股自动排除）
 → 被数据否定

 实测:
 全表 5,324 只 → 按判据筛 → 5,184 只（排除 140 只）
 那 61 只断裂股的命运:
 被排除: 只有 7 只
 仍在池中: 54 只
 → 断到干净池里的比例 = 54 / 5,184 = 1.0%

 而池中那 54 只全是正常大票:
 000333 美的 · 000651 格力 · 000858 五粮液 · 600036 招商银行 · 000568 泸州老窖
 002032 苏泊尔 · 000596 古井贡酒 · 300274 阳光电源 · …
 → 它们的断裂不是"退市"造成的
 → 是复权算错 → 任何股票池判据都救不了
```

### → 这条实测有两个后果

```
① "数据层重做"由"建议"变成"必需"
 先前我说"紧迫性下降了"（因为负数只有 4 只）—— 那是只看负数的结论
 现在看断裂→ 54 只正常大票在池中带病
 → 一个随机 20 只组合 → 期望 0.2 只→ 约 18% 概率踩到一只
 → → 回测结论有近两成概率被污染 —— 这不能接受

② 第 7 条规矩（先量再下结论）这次生效了
 我先跑了这个查询 才开口
 → 结果否定了自己的假设 —— 而这是好事
 → 若我先写文档再说"池子判据够用" → 后面所有回测都会建在坏数据上
```
