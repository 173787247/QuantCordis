# QuantCordis 回测器设计

## 一、设计原则

```
 market 对象自己写 → 不 import 外部回测器
 → 只实现策略需要的接口: get_recent_kline(code, period, count)
 → 只返回当前索引之前的数据 → 避免未来函数
 策略函数复用 → 从 QUANTCORDIS_STRATEGY_ROOT import
 → 为什么是"复用"不是"依赖":
 · 复用策略算法（纯函数 签名统一）
 · 不复用引擎 · 数据库 · 调度
 → 路径显式配置 → 没有它数据层照样能跑
 成交假设: 信号在 K_i 收盘出 → 用 K_{i+1} 开盘成交 （参考实现也这样）
 成本: 佣金 万2.5（双边）+ 印花税 千0.5（卖出单边）
 没做: 滑点 · 冲击成本 → 已知缺口
```

## 三、修法（下一轮）

```
 首选: 回测不模拟股数，用"全额买入/卖出"
 · 买: 全部资金按当日开盘价买入 → 记录份额 = 资金 / 价格
 · 卖: 全部卖出 → 份额 × 价格
 · → 测的是收益率序列 → 不受资金规模影响
 · 而"10 万能不能买"是组合构建的问题 → 该在那一层处理
 备选: 按复权比例放大初始资金（不够干净）
 无论选哪个: 都必须显式报出"因价格过高而未能成交"
 → 而不是静默 0 笔
```

## 四、 净值可复现性判据（还没验）

```
 判据: 同一 (策略, 票, 区间) 的净值曲线应当可复现
 现状:
 · 参考: 600519.SH × ma20_hold × 2018-2026
 · 新回测器: 0 笔 → 还没法比
→ 修完"买不起"之后才能做这个对照 → 那时不一致就说明有一边错
 注意: 复权口径会影响可比性（本回测器默认后复权）
 → → 两者的收益率应当相同（复权方式不改变收益率）→ 所以可以对照
```

## 五、 修完"买不起"之后的首轮对照

```
 改法: 回测不模拟整数股数 → 用浮点份额
 · 买: shares = cash / (px × (1 + commission))
 · 卖: cash = shares × px × (1 − commission − stamp)
 · nav = cash + shares × close
 同时显式报出实盘约束:
 「有 116 次按当时的开盘价，100000 元资金买不起 1 手」
 → 不静默 而且说明"回测用浮点份额，不受它影响"

 结果（600519.SH × ma20_hold × 2018-01-02 → 2026-06-30 · 2,126 天）:
 新回测器: 收益 +34.93%· 交易 232 笔· 信号 233 个 · 回撤 35.52%
 参考: 交易 232 笔 · 买入持有 210.26%
 → 交易数完全一致 → 信号层对齐
```

## 六、 一个必须澄清的概念（我前面说错了）

```
 我说过「复权不改变收益率」 —— 不精确
 精确: 复权不改变日收益率序列
 · 后复权 = 分红再投资→ 累计收益更高
 · 不复权 = 分红拿走→ 只算价差 → 累计收益更低
 → → 两种口径的"买入持有"本来就不该相等

 验算（茅台 2018-01-02 → 2026-06-30）:
 · 不复权价: 703.85 → 1,288.00 → +82.4%（分红拿走）
 · 后复权价: 4,439.09 → 9,878.39 → +123.76%（多出 41 个点 = 分红再投）
 · 库里前复权: +210.26% → 而它有 59.6% 的断点 → 不可信
→ 新回测器更可信 —— 因为它的日收益序列通过了金标准（6,089/6,093）
```


```
 原判据: 净值应当一致 —— 错（两者用的复权口径不同）
 修正为两条:
 ① 信号层一致: 交易数、买卖日期应当相同
 → 实测: 232 = 232 通过
 ② 收益层可解释: 差异应当能归因到复权口径
 → 前复权（旧）算出的累计收益偏高 · 后复权（新）居中 · 不复权偏低
 → → 顺序: 不复权 < 后复权 < 前复权（当标的长期上涨且有分红时）
 → 实测: 82.4% < 123.76% < 210.26% 顺序对
```
